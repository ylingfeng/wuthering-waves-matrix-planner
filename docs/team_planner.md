# 本地矩阵配队面板

在独立配队仓库根目录双击 `start.cmd`，然后打开 http://127.0.0.1:8765 。
也可以运行 `python -X utf8 -m tools.planner_dev_server --port 8765`。该开发服务仅需 Python 标准库；当前目录与保存规则见 [项目说明](../README.md) 与 [静态网站说明](static_website.md)。

下文保留早期 Python 面板的实现记录。旧编辑器仍可用 `python -X utf8 -m matrix_planner.planner_server --port 8765` 启动，依赖 `requirements.txt`；不要与当前开发服务同时占用同一端口。旧记录中的页面文案、默认分值与保存位置，以当前网页及上述项目说明为准。

## 使用

- 顶部“配队范围”：我的角色／全角色。全角色计算时临时纳入已实装但未拥有的角色，按基础体力/本周覆盖值与五星1.1、四星1.0默认权重参与，不修改拥有状态；未拥有角色的自定义权重不在此模式使用。
- “剩余体力按主辅奶补队”默认开启：先精确分配已有候选，再对剩余体力生成主C＋辅助＋奶妈兜底队，暂定队权0.1，不视为实测配队。兜底不改变第一阶段选队，也不绕过手动禁用的组合。结果按最终得分从低到高排序。
- 定位来源见 `config/team_planner/role_sources.json`；角色卡可修改定位。奶妈标志与奶妈定位保持一致，体力独立设置。
- 莉莉：用户确认同奏奶妈、基础体力2；尚未实装，CSV“已实装”留空，所有模式强制排除。心/锁暝/莉莉只记录为待验证组合。

- 角色库：切换全部/已拥有/未拥有，勾选可用角色，修改奶妈标记、基础体力、本周变动体力和角色加权。
- 本周变动体力是覆盖值，不是加法；留空回退到基础体力，0 表示本周不可出战。
- 初始名单58人，其中原有37人可用、新增21人不可用。漂泊者男女/属性合并为一个角色，四属性共用体力。
- 未明确指定的新增角色不自动标奶妈，基础体力默认1；可在网页调整。
- 候选队伍：支持三人编队、优先分、参与开关、必选、漂泊者属性和多个输出轴。
- 必选队伍会先占用规划体力，若角色不可用或必选互相冲突，明确报错。
- 编辑后点击“保存修改”；“计算最佳配队”会先保存未保存的修改。
- 机制推导替补默认不参与计算，可在配队结果页勾选后重算。
- 输出轴的选择/文本编辑用于配队规划资料，不会自动编译成战斗脚本；现有战斗配置不受影响。

## 数据与来源

- `character.csv`：角色名称、奶妈标注、基础体力、本周变动体力、可选属性、可用、加权。非奶妈、非变动和不可用值均为空。
- `assets/characters/*.png`：官方Wiki角色图鉴公开PNG，统一限制图片尺寸；来源链接见同目录 `sources.json`。
- `config/team_planner/catalogue.json`：工坊/Wiki种子库，196种组合；工坊原始60个轴全部保留。
- `config/team_planner/teams.json`：用户编辑副本，首次启动从种子库创建，后续重启不会重置。
- `config/team_planner/last_plan.json`：最近一次求解结果，含每个角色剩余体力。
- `config/team_planner/*.previous.*`：最近一次保存前的备份。
- `reference_analysis/matrix_teams/wiki_quotes.json`：官方Wiki配队原文及链接。
- 工坊目录：https://okwwcharcode.ok-script.com/teams.json
- 官方Wiki：https://wiki.kurobbs.com/mc/home

配队依据分为工坊明确矩阵、工坊通用参考、Wiki明确配队、机制推导待验证、自定义。
替补推导仅在Wiki明确推荐的输出搭档中，将守岸人/维里奈替换为其独立攻略中注明“所有角色”适配的白芷/穗穗；这不是三人组已实测的证据。
未拥有角色的候选同样保留，获得角色后可以直接启用。

## 优化规则与当前结果

2026-10-23 两两搭档补查后，候选库已更新至212种；原有37位角色可用的直接依据候选69种，最多11队；包含待验证推导为99种，也为11队。下方9/10队为首次建库快照。补查来源和限制见 [两两配队补查](../reference_analysis/matrix_teams/pair_research.md)。

每队三名不同角色，选一次各消耗1点规划体力，不强制奶妈。
同一三人组合只选一次；槽位顺序、多套轴和漂泊者属性不额外增加独立组队数量。
同队角色加权相乘：队伍加权 = 角色1加权 × 角色2加权 × 角色3加权。
初始爱弥斯6、达妮娅6、清宵3、心3、绯雪3，其他角色1。例如爱弥斯/达妮娅/千咲为36。
星级更新：按官方Wiki图鉴增加星级列，五星默认加权1.1、四星1.0；以上明确指定的6/3与其他自定义非1权重不覆盖。加权已包含这项默认差异，不再额外乘一次星级系数。当前图鉴58人中46名五星、12名四星；此前使用其他角色1的示例为旧规则。
队伍得分 = 队伍自身权重 × 角色1加权 × 角色2加权 × 角色3加权。
先最大化队伍数量，再最大化所选队伍得分的总和。队伍自身权重支持0到100的小数。
例如爱弥斯/达妮娅/千咲自身权重2时得分为2×6×6×1=72。
原“优先分”字段（内部字段名priority）现在作为队伍自身权重参与乘法，不再作为最后的同分比较。
既有权重是资料依据的初始暂定值，新增普通备选权重较低；均可按实战修改，不代表伤害或矩阵分数。
小候选集使用精确搜索，超过20种候选使用两阶段整数规划，并要求证明最优后才显示结果。

初始37位角色、本周琳奈2体力时：只用工坊与Wiki直接推荐，有55种可用候选，最多9队；
包含待验证替补时有84种可用候选，最多10队。44点体力给出的14队仅为无组合限制的数量上界。
账号练度、武器、共鸣链、敌人和输出轴实际适配均未纳入强度评分。

## 逐角色攻略补充（2026-10-23）

本轮新增92队，共347队，保留60套工坊轴。逐角色来源见 reference_analysis/matrix_teams/all_character_review.md。角色卡的“查看配队”会进入候选页并按该角色筛选。新增推荐初始队权2；已有队伍权重、参与开关、角色配置保持不变。攻略为通用配队参考，不代表矩阵实测排名。

研究脚本依赖见 tools/requirements-research.txt。执行 python -m tools.research_all_characters --cached 可重新解析已下载的60篇攻略；去掉 --cached 会更新索引并复用本地页面缓存。python -m tools.build_team_catalogue 仅更新种子库，不覆盖在线编辑的数据。


主C版本加成：仅定位为单一“主C”的已实装角色参与，辅助、奶妈及兼任辅助者不变。V1.0至V3.7按实际版本序列，每晚一版乘数增加0.002，当前最高1.042；缺失或未知版本不加成。实际角色权重=原权重×版本系数，全角色模式未拥有者先用星级基础权重再乘系数。CSV手动权重不改。

网络直接配队来源加成：有HTTP(S)来源的工坊明确矩阵、工坊通用参考、Wiki明确配队、攻略主流配队，额外乘1.03；多个来源不叠加。机制推导、治疗替换、用户自定义、兜底不自动享受。角色练度和队伍自身权重继续由用户编辑，原值不覆盖。最终队伍得分=队伍自身权重×来源系数×三名角色实际权重。

最新权重规则：角色实际权重=(链度+1)×基础分×用户练度。链度为0～6下拉选择，默认0；用户练度已统一初始化为1，可自行编辑（CSV加权列）。基础分默认1，仅新主C按版本小幅上浮，星级不再产生额外加成。全角色模拟中未拥有者默认0链、练度1。新规则覆盖此前星级默认分与旧练度初始值。

来源收录偏好：优先B站明确标注矩阵的教学或实战，核实三人组合，记录链接及可获取的链度/装备要求。用户提供的视频组合可先收录为“用户确认·视频配队”；未实际读取视频时不得标为已核实，也不自动套用已核实网络来源加成。

2026-10-26基础分规则（替代此前来源加成）：B站视频来源2.5；Wiki直接配队2；工坊轴说明明确含矩阵/矩陣2；其余含兜底1。多个来源取最高，不再额外乘1.03。机制推导中引用的Wiki链接不视为直接配队。浏览器现有队伍做一次性基础分迁移，之后手动调整保留。

2026-10-26来源审查：默认库配队基础分最终改为视频标题/简介明确支持2.5，Wiki原文明确三人及属性1.5，工坊明确矩阵2，其他1。无矩阵说明及矩阵视频佐证的工坊队伍默认不参与。全库核对报告：reference_analysis/matrix_teams/source_audit_all.csv/json。B站逐队搜索记录：reference_analysis/bilibili/team_search_queue.json；请求受限时停止，pending/access_limited不表示无视频。浏览器已保存的priority和enabled不被来源审查覆盖，仅更新default_priority/default_enabled/source_audit。用户在队伍编辑器可主动采用默认分。保存前保留上次版本，恢复按钮可切回；此前已经覆盖且未导出的旧个人值无法从工程备份推断。


## 当前规则（2026-10-26，替代上文历史规则）

固定配队基础分：B站视频明确三人且含矩阵关键词 2.5；工坊说明含矩阵关键词 2.0；Wiki原文明确配队 1.5（无须矩阵关键词）。满足任意一类默认参与，其余默认关闭；多来源并列显示，固定分取最高，不叠加。网页允许用户自行开启或关闭候选。

共389个候选（原359个逐队搜索，另新增并逐队搜索30个）；182个默认参与，207个默认不参与。检索记录在 reference_analysis/bilibili/browser_search，证据基于搜索标题、简介及歧义角色标签核对，不表示逐帧看过视频。证据类型7类：B站矩阵94队、工坊矩阵7队、Wiki明确124队、B站非矩阵13队、工坊未注明矩阵39队、一般攻略189队、未核实或推导86队。类型可重叠，不能相加作为队数。

浏览器队伍得分 = priority（固定来源基础分） × user_weight（独立用户配队加权，默认1） × 三名角色实际加权。旧配置的手动priority换算为旧priority / 旧default_priority，并保留legacy_priority；基础分随库更新，用户加权不覆盖。旧默认值对应用户加权1。

导出格式 matrix-planner-v2 仅包含角色个人设置、队伍用户加权/开关/备注/轴及队伍标识；不导出来源分和证据库。导入始终从当前库取得固定分及证据，额外注入的priority/default_priority/source_audit无效。兼容v1旧配置导入。浏览器保存和导出仍是不同操作。

页面入口 /characters/、/teams/、/results/；静态目录入口支持直接访问、刷新、前进后退，无须后台或服务器重写。修改index.html后运行 python -m tools.build_web_routes 同步三个入口，发布脚本会自动同步。file://离线访问使用hash切页。
